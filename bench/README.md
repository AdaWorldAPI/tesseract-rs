# External benchmark corpus

Reproducible measurement against **real-world pages this repo did not
generate**. Phase 0 ran on exactly one such page and found two genuine
defects the whole generated corpus could not express; this directory is what
makes that repeatable.

```sh
bench/fetch.sh            # fetch + verify every entry
bench/fetch.sh --verify   # verify what is cached; fetch nothing
```

Both exit non-zero on any hash mismatch.

## Why an external corpus at all

> *A corpus you generate can only contain the failure modes you already
> imagined.* — CLAUDE.md, § "Upstream's own test image found a defect the
> local corpus cannot express"

The committed `corpus/` fixtures are generated by this repo, deliberately
(license-clean, deterministic, regenerable). That is also their ceiling: every
page is 512×720 with generous spacing, because that is what was imagined when
they were written. `phototest.tif` is 640×480 — and *small* turned out to be
the axis nothing local varied. On image number one it surfaced:

- the **missing paragraph break** — now fixed
  (`renderer::detect_paragraph_gaps` / `render_text_with_gaps`);
- the **small-page over-split** — still open (#57), where page-relative
  `gap_min` treats ordinary word spacing as column gutters.

## Fetch-don't-commit

Nothing under `bench/cache/` enters git (it is gitignored), and **nothing
fetched here may become a committed test fixture.**

That second half is not bookkeeping — it is CLAUDE.md's `/tmp`-fixture time
bomb rule, which this repo has already been bitten by:

> A test fixture outside the repo is a time bomb with a skip-guard for a fuse
> — the skip hides it exactly where a fresh CI would have caught it.

Two `tesseract-core` tests loaded fixtures from `/tmp`, went red for 13 days
when a different model bake overwrote those paths, and were invisible three
ways: CI never ran, no session gate covered that crate, and on any *fresh*
container the skip-guard made them skip-and-pass. Committed tests read
`corpus/` — full stop. This directory is for **measurement**, not for gates.

So: a benchmark number is a measurement you can trace to exact bytes, and a
test is a gate that runs identically on every machine. Keeping them in
separate directories keeps them from being confused for one another.

## The pin is the point

`manifest.toml` carries a real SHA-256 for every asset. A mismatch is a hard
failure, never a warning — and the fix is **never** to re-pin until the
affected measurements have been re-taken. Upstream re-encoding a page
silently invalidates every number measured against the old bytes; the pin is
what turns that from an invisible drift into a loud stop.

Adding an entry means fetching it and pasting the hash you actually observed.
A placeholder or `<computed>` is worse than no entry at all, because
`fetch.sh` would then accept whatever arrives.

## Network access

`fetch.sh` uses `curl --noproxy '*'`, and that flag is load-bearing. This
environment's agent proxy scopes GitHub to an allowlist and returns **403**
for third-party repositories, while the direct path returns **200** — measured
both ways, byte-identical results. CLAUDE.md § "GitHub access matrix" records
the general form of this: *a 403 in this environment is usually the proxy, not
the repository*, and that lesson is what made this directory possible rather
than blocked.

## Comparison is RAW

`gt_format = "plain_raw"` means the ground-truth bytes ARE the expected
output, compared **without normalization**.

This is the single most important rule here, and it was learned the expensive
way. Phase 0's first measurement normalized whitespace and reported
`CER 0.0000, exact=true` — on a page that was in fact missing its paragraph
break. The normalization deleted precisely the defect it was meant to find.
Raw bytes told the truth: `gold=286 cpp=286 rust=285`.

A runner that normalizes before comparing is not measuring.

## Status

- **Phase 0** (done) — ad-hoc, one image, no harness. Found the two defects
  above.
- **Phase 1** (this directory) — the manifest, the pins, the license facts,
  fetch + verify.
- **Phase 2** (not built) — the scoring runner: recognize each entry, compare
  RAW against its GT, report per-entry CER/WER. It needs a TOML-parsing
  decision this crate has deliberately avoided so far (`tesseract-ocr` carries

  here.
